Family-aware admin enrolment

Today the admin can enrol through three inconsistent doors, and two of them (single-enrol, bulk-import) resolve the challenge with the public-money gate sellable() — so they literally cannot reach an institutional (Acharya / school) stream. Only batch-create can, by picking a whole challenge. This proposes one adaptive enrolment flow that adapts by stream family — the same taxonomy that already drives onboarding — so demo · school-B2B · Acharya · manual-student all work in unison.

The one rule: the admin picks a specific challenge (grouped + labelled by family), never a fuzzy (stream, plan) resolved through a money gate. That single change makes every family reachable — demo (is_demo=true) and institutional (is_listed=false) included — while public checkout keeps using sellable() untouched.

The same family-aware contract applies to every admin entry point — the CSV bulk uploader included. Whichever door the admin uses, the challenge is resolved the same way and the same family rules apply.
