Yashodarshi Desk — group the queue by stream-family

The evaluator desk today groups work into two tier lanes (₹4999 premium · 7-task) and sorts by SLA. The stream is loaded per row but shown only as inert grey text. As streams grow (7 public + 3 Acharya + future Corporate/Gov/College), a group-by stream-family control lets an evaluator batch by context — driven by the same Challenge::onboardingFamily() the platform already uses.

Recommendation: start with a lightweight group-by control (a segmented toggle: Lane — today's default — vs Family), not heavyweight tabs. The evaluation work is identical across families (same rubric), volume is low, and the data is already fetched — so this is a presentation change, reversible, and earns its keep the moment the queue gets long or a family needs different columns.

Why this is cheap + safe
  • Data is already fetched. EvaluatorDesk::queueFor() already loads the Challenge per row and can read Challenge::onboardingFamily() — the desk item array just needs to expose stream/family as top-level fields; the Blade groups by them.
  • One taxonomy, reused. The family (children/adult/educator) is the same registry that drives onboarding — the evaluator grouping can never drift from it.
  • Reversible & low-risk. A toggle over one queue, default = today's Lane view. Promote to real tabs only when a family needs different columns (e.g. Corporate adds employer fields) or the queue gets long.
  • Batching benefit even at low volume. Scoring a run of children's tasks, then a run of educator tasks, keeps the evaluator's rubric exemplars consistent.
