AStreams model & the B2B/B2C refactor

A.1 — The model (verified)

A "stream" = a program_key. Source of truth: SellableChallengeSeeder.php. PROGRAMS = 7 public/B2C; INSTITUTIONAL_PROGRAMS = admin-only/B2B (Acharya). Split derived in ChallengeController::applyAudienceAndListing().

A.2 — Refactor to is_institutional (corrected)

Replace the teacher-specific audience='acharya' tag with a coarse is_institutional flag (derived from INSTITUTIONAL_PROGRAMS membership) so the B2B list can grow past teachers. Two red-team corrections:

  • FIX #M This is a real schema migration (add is_institutional; the earlier migration already added audience+is_listed), with a tested down(). Renamed from "no data migration" to "no data backfill" (the flag re-derives from program_key).
  • FIX #1 Keep is_listed — do not drop it. It is read on the money path (below); make it a derived/generated value that always equals !is_institutional, so no money-path code changes. Only audience is retired.

A.3 — Educator content keys on stream family, not the flag

is_institutional gates store/enrolment/charge only. The teacher-specific content (study guide, pace, "Acharya" labels) keys on the stream family program_key LIKE 'acharya_%' — so a future Corporate/Government institutional stream never inherits the teacher path.

A.6 — Structural isolation (new, per red-team #9)

HIGH #9 Isolation must be structural, not procedural — today it relies on every writer routing through one controller method, and is_listed defaults TRUE.

  • Add a Challenge::saving() observer (or DB generated column) that force-derives is_listed = !isset(INSTITUTIONAL_PROGRAMS[program_key]) on every save — so listing can never diverge from stream family regardless of write path (seeder, import, mass-assign).
  • Remove is_listed/audience from $fillable (no mass-assignment).
  • Regression test: create an Acharya challenge via the seeder (not the controller) and assert it is absent from scopeSellable/scopeListed and 422s in resolveOfferChallenge.

A.7 — Single-source the second catalogue copy (per red-team #M)

CheckoutController::PROGRAM_KEYS is a hand-maintained catalogue copy (comment says "6", lists 7 — already drifted). Replace with array_keys(SellableChallengeSeeder::PROGRAMS); do not union the institutional keys. Also add a config feature flag (§I).

BOnboarding — already built; repoint onto stream family

Acharya educator onboarding already exists (#1394). During the refactor, the onboarding + pace gates move off audience onto the stream family (acharya_%), NOT onto is_institutional (per red-team #M): the stream declares its onboarding family — student (age refines minor/adult) · educator (Acharya) · future Corporate/Gov (their own). Keying pace/onboarding on the flag instead of the family would silently mis-serve a future non-teacher institutional stream.

CEnrolment sets stream + flag (invisible)

Enrolment records the program_key; is_institutional derives from membership (invisible to the operator). Institutional enrolment stays the manual/admin batch path — no self-serve checkout. Order: challenges → onboarding → enrolment.

D.3 — The two mechanisms (were missing — now specified end-to-end)

CRIT #3 ① benchmark_mode = "single" (saffron champion)

The engine carries 3 benchmark layers everywhere (dev,champ,comp). Do not change the data shape.

  • Storage: encode each Acharya pillar/ability/IntelliGraph/age value as a full 3-layer entry with the champion value repeated across all three — so every existing unpack site keeps working (no crash).
  • New flag: add benchmark_mode to the stream dict ("triple" default | "single"). Both benchmark_compare.py and the render (scorecard-full.html) read it: in single mode, emit/draw one saffron series ("All-India ASLI Champion Benchmark") instead of three bars.

CRIT #4 ② has_pathways = false (no Career Pathways)

  • Assembly: in build_21task_scorecard, branch §7 off when has_pathways=false; pass pathway=None to build_section8 (already null-safe at section8.py:85).
  • Validator: make _REQUIRED_21 in validate.py stream-aware — pathway-less streams require the "Final Conclusion & Summary" instead of section7_career_pathways (else the fail-closed gate rejects the card). validate.py is now in the blast radius.
  • Render: guard the §7 grid + the §8 pathway-match card.

D.4 — §1-F "why-notes" are a content dependency (per red-team #2) content

CRIT #2 build_21task always calls section1f_abilities(), which fails loud if a stream — or any of its 15 abilities — lacks an authored "why this ability matters" note. Those exist only for the 7 student streams → the first Acharya card crashes. This needs 15 educator notes × 3 streams of Sutirtha content (and a check of §5/§6 library content). Added to ability_notes.py change-set + the owner list (§H). A CI test builds each Acharya §1-F so a missing note fails the pipeline, never a teacher.

D.5 — Deploy canary must exercise Acharya (per red-team #10)

The deploy self-test pings stream=neet only and skips-and-passes when a fixture is absent → Acharya defects would ship green. Fix: add Acharya fixtures + program_map entries, and make scorecards:selftest ping at least one Acharya stream (or iterate all mapped streams).

D.6 — Test-suite split, not weaken (per red-team #6)

~6 guards hardcode "the 7 streams" / require top5 / unpack 3-tuples. Fix: split into a STUDENT_STREAMS class (strict: 3-layer + top5 + monotonic) and an INSTITUTIONAL_STREAMS class (single benchmark, no top5, no pathways), each with its own oracle — so both stay strictly enforced. Do not loosen the existing guards to green.

D.7 — "All 64 assessed → 15 priority" coverage (per red-team #M)

Confirmed by Sutirtha, but not engine-enforced — an expired task can render an ability "not assessed". Add a validate-time coverage note, or state the guarantee as conditional on task completion.

  • Scoring code, evaluator, task→ability mapping, the AACE64 rubric. ✔
  • The 7 student streams' output — protected by the CI parity gate in §I (per red-team #5).
