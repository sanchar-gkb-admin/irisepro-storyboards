A3 · The engine side — a "stream" is a rich content bundle

  • Benchmark norms (benchmarks.py) — per-pillar & per-ability targets × 3 brackets, IntelliGraph zones, top15/top5, age. The "what good looks like."
  • Pathways / roles (pathways.py) — career/growth pathways.
  • Ability "why" notes (ability_notes.py) — §1-F copy, per-stream, and it RAISES if the stream is missing.
  • §6 impact label (STREAM_S6_LABEL, default "Exam Impact").
  • program_map + tier_map — the mapping. Missing ⇒ SC_UNKNOWN_STREAM ⇒ the learner completes tasks but gets no scorecard (stranded).

A4 · The rubric & scoring — per TASK, not per stream

Each task's task_scores.attribute_score = {pillar:{ability:5}} is pure ability membership (which of the 64 it measures; 5 = scale marker, not a weight). The Yashodarshi scores each measured ability 0–5; the engine computes % = sum ÷ (5 × instances) × 100 and only benchmarks it against the stream norms. There is no per-stream rubric — the rubric is the task. Fixed 0–5, equal weight (no way to weight abilities).

A5 · If it's a new AUDIENCE (not just a stream) — cross-surface

A new audience adds a discriminator (challenges.audience) that must reach every surface that frames the experience: onboarding, the evaluator cockpit + ability guidance, the scorecard render + the engine contract, comms, and admin/reporting. See Part B for the full matrix.

A7 · Who owns what

Engineering: the discriminator field, the list wiring, surface branches, the engine contract, guards/tests. Sutirtha / KMM (content): the tasks + per-task rubric, the benchmark lens, the ability "why" notes, the pathways/impact wording, and (for a new audience) the onboarding manual + framing copy.

Part B Acharya — requirements, acceptance surfaces, student-flow impact

Decision: add challenges.audience ∈ {student, acharya} (default student) as the single discriminator, defined on the challenge (known at enrolment; every surface already holds the challenge). Acharya = teacher = audience=acharya + not-listed.

B5 · Build phasing

  1. Phase 1 — Enablement (unblocked, red-teamed): audience + not-listed fields, INSTITUTIONAL_PROGRAMS list, validation/dropdown, admin create, manual enrolment, fallback closures, regression test, adult-DOB import. Teachers can enrol + do tasks.
  2. Phase 2 — Surface branching: onboarding gates (class + manual + copy), evaluator badge + guidance surface, admin audience filter, student-audience scoping.
  3. Phase 3 — Content-gated (needs Sutirtha): engine acharya stream + program_map (SC_UNKNOWN_STREAM gate), scorecard render copy, teacher manual, ability guidance. Required before the first cohort's scorecards generate.
